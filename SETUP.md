# Закрытый раздел «Записи эфиров» — настройка

## 1. Хранилище Blob (private)
Vercel → проект → **Storage → Create → Blob → Access: Private**, подключить к проекту (Production, Preview).
Автоматически появятся `BLOB_STORE_ID` и OIDC-токен — отдельный токен не нужен.

## 2. Переменные окружения (Settings → Environment Variables)
| Имя | Что |
|---|---|
| `BOT_TOKEN` | токен бота из @BotFather (тот бот, из которого открывается мини-апп) |
| `ADMIN_IDS` | ваш Telegram ID (несколько — через запятую). Эти люди получают заявки, имеют доступ и админ-панель |
| `TG_WEBHOOK_SECRET` | любая длинная случайная строка (A–Z, a–z, 0–9, `_`, `-`), например `openssl rand -hex 24` |

После добавления переменных — **Redeploy**.

## 3. Вебхук бота (один раз)
```bash
curl -s "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -d "url=https://<ваш-домен>/api/bot" \
  -d "secret_token=<TG_WEBHOOK_SECRET>" \
  -d 'allowed_updates=["callback_query"]'
```
Если у бота уже есть другой вебхук — этот его заменит.

## Как устроено
- `api/app.js` — статус доступа, список записей, заявка, временная ссылка на аудио (30 мин).
- `api/admin.js` — админ-панель (только `ADMIN_IDS`): доступ, загрузка MP3, удаление.
- `api/bot.js` — кнопки «Одобрить» / «Отклонить» в боте.
- Каждый вызов проверяет подпись `initData` на сервере. Аудио в приватном Blob, публичных ссылок нет.
- Данные (одобренные, заявки, список записей) — `db/state.json` в том же приватном Blob.
